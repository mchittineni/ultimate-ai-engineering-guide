# Security Policy

## Scope

This policy covers security issues in the `ultimate-ai-engineering-guide` repository, including its content, scripts, and generated output.

## Reporting a Vulnerability

If you discover a potential security vulnerability, please report it responsibly and in private.

- **Do not** open a public issue for security concerns.
- **Do not** include screenshots of private information (e.g., interview scheduling or communications) in any report.
- **Do not** include logs, full code snippets, or any personally identifiable information (PII).

To report a vulnerability:

1. Go to the **Security** tab of this repository.
2. Click on **Report a vulnerability**.
3. Select **Security Advisory**.
4. Fill in the form with a clear, concise description of the vulnerability and steps to reproduce it.

Alternatively, you may contact the maintainer directly:

- GitHub: [@mchittineni](https://github.com/mchittineni)

## What We Consider a Security Issue

Examples of issues that should be reported under this policy include:

- **Sensitive Data Exposure:** Accidental inclusion of PII, interview candidate details, company-specific private information, or credentials in the repository or generated outputs.
- **Insecure Practices in Content:** Advice or code examples that could lead to security vulnerabilities if blindly followed in production.
- **Supply Chain Risks:** Security issues in the Python scripts or their dependencies that could be exploited.

## What We Do Not Consider a Security Issue

- General content issues like factual errors, outdated information, or suggestions for improvement (unless they pose a direct security risk).
- Requests to remove or anonymize previously contributed content (unless it contains PII or private information).

## Handling of Reports

All reports will be reviewed promptly and handled confidentially. We will:

- Acknowledge receipt of the report within 48 hours.
- Provide a timeline for the investigation and resolution.
- Communicate updates regarding the status of the vulnerability.

## Content Removal and Remediation

If your report concerns sensitive information in the repository:

1. We will remove the sensitive content as quickly as possible.
2. We may require you to confirm that you are the owner of the data or have permission to request its removal.
3. We will follow up to ensure the content has been completely erased (including Git history if necessary and feasible).

## Public Disclosure

Public disclosure of a security vulnerability will be coordinated between the reporter and the maintainer.

- We will not disclose the vulnerability until we have:
  - Confirmed the vulnerability with you,
  - Issued a fix, and
  - Given users a reasonable time to apply the fix.
